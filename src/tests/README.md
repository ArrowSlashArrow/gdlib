# Writing tests

This folder holds all of gdlib's unit tests. It is compiled only for `cargo test`, through `#[cfg(test)] pub mod tests;` in `src/lib.rs`.

```sh
cargo test --lib                          # everything
cargo test --lib tests::object_properties # one file
cargo test --lib move_trigger             # anything with "move_trigger" in its name
cargo test --lib -- --nocapture           # also show println! output (benchmarks, dumps)
cargo test --lib -- --ignored             # run the #[ignore]d scratch tests
```

## The rule: test what the code *should* do

A test describes the **intended** behaviour, not what the code happens to do today. If a test fails because the library is wrong, keep the test and fix the library. Never weaken an assertion just to make it pass. Do change a test when the test itself is wrong, for example when it relies on a format assumption that turned out to be false.

## Where does my test go?

Pick the file by what the test **mainly** checks, not by which struct it uses:

| File | Put a test here when it checks… |
|---|---|
| `serialisers.rs` | struct → string, plist dict or bytes. Asserts on the *output text*. |
| `deserialisers.rs` | string, plist or bytes → struct. Also: malformed input must not panic and must fall back sensibly. |
| `roundtrips.rs` | `parse(serialise(x)) == x` (or the reverse) for in-memory values. |
| `object_properties.rs` | anything implementing `ObjectProperties` (triggers, gameplay objects, `StartposConfig`, …). |
| `enum_conversions.rs` | number ↔ enum, `GDVersion`, `ColourChannel`, `Item`, achievements, object-type enums. |
| `accessors.rs` | getters, setters, builders (`with_*`, `set_*`, `add_*`), `get_property` / `has_property`, group helpers. |
| `game_logic.rs` | maths that copies GD's behaviour: item edit/compare, RNG, seeds, rotation. |
| `files.rs` | reading or writing real files (`test_gmds/*`, `export_to_*`, `from_gmd`, `decrypt_file`, …). |
| `local_savefiles.rs` | anything that needs the user's own GD install (`from_local`). |
| `benchmarks.rs` | timing only. Use the `benchmark` helper. Should not assert on speed. |

A new feature usually needs tests in **more than one** file. A new level field, for example, needs a serialiser test, a deserialiser test and a round-trip test.

## Shared helpers (`mod.rs`)

Child modules can call these through `use super::{...}`:

| Helper | Use |
|---|---|
| `test_config()` | a non-default `GDObjConfig` (position, groups) for building objects |
| `default_block()` | a plain block (`GDObject` with id 1) |
| `sample_level()` / `sample_list()` | a `GDLevel` / `GDList` where **every** field is set to a non-default value |
| `assert_levels_eq(a, e)` / `assert_lists_eq(a, e)` | field-by-field comparison with readable diffs (`GDLevel` has no `PartialEq`) |
| `object_kv_pairs(s)` / `values_of(s, key)` | split a raw object string into key/value pairs, or get every value stored under one key |
| `generated_path(name)` | `test_gmds/generated_<name>`, the place to write output files (gitignored) |
| `benchmark(name, f)` | runs `f`, prints how long it took, returns its result |
| `CONFIG_PROPERTY_IDS` | every property id that `GDObjConfig` owns rather than the object's property list |

Add a helper to `mod.rs` only if more than one file will use it. Otherwise keep it private in the file that needs it.

## Recipes for common changes

### New trigger / object (new `ObjectProperties` implementor)

Add a single `object_properties_suite!` call to `object_properties.rs`. It generates 12 tests for the type: valid object id, no duplicate properties, no config properties, value types match `PROPERTY_TABLE`, `from_config` → `get_property`, rejects foreign ids, accepts a bare object, and round trips through `from_config`, the object string and a whole level.

```rust
object_properties_suite!(my_trigger: MyTrigger {
    ids: [MY_TRIGGER],                 // every object id this type can have
    samples: vec![                     // cover every enum variant and every Some/None
        MyTrigger { target_group: 3, mode: MyMode::A, extra: Some(2.5) },
        MyTrigger { target_group: 4, mode: MyMode::B, extra: None },
    ],
    compare: direct,                   // see below
});
```

- `samples` is an expression that gets **evaluated twice**, so the type doesn't need `Clone`. Use non-default values, otherwise the round trip can't tell "kept" from "lost".
- `compare`:
  - `direct` if the type derives `PartialEq + Debug`
  - `debug_repr` if it only derives `Debug`
  - a hand-written `fn compare_x(actual: &T, expected: &T)` that checks each field otherwise (see `compare_pulse`, `compare_orb`)
- If the struct is generated by `object_descriptor!` (so it derives `Default`), also add a line to the `bare_object_is_default!` list.
- If one type maps to several object ids (pads, orbs, portals), add an `every_<x>_has_its_object_id` test that checks each variant ↔ id pair.
- Add standalone tests below the suites for behaviour the suite can't see. Examples: which properties each mode writes (`move_trigger_mode_properties`), or parsing a real object string copied from the game (`end_trigger_from_object`).

### New `GDObjConfig` field or attribute

1. If it owns a property id, add the id to `CONFIG_PROPERTY_IDS` in `mod.rs`. Otherwise the suite won't catch triggers that write it a second time.
2. `serialisers.rs`: it's written with the right key, and it's left out when it has its default value.
3. `deserialisers.rs`: it's parsed into the config, not into `properties`.
4. `roundtrips.rs`: add it to the "every config field" object.
5. `accessors.rs`: its builder and setter agree, and `get_property` / `has_property` see it.

### New `GDValue` variant / `GDObjPropType`

- `roundtrips.rs`: add a case to `sample_value()` and `prop_type_of()`. The per-property round-trip test then covers every property of that type in `PROPERTY_TABLE`.
- `serialisers.rs` / `deserialisers.rs`: the exact text format, plus malformed input (empty string, garbage, overflowing numbers) that must not panic.

### New enum

Use the macros in `enum_conversions.rs`:

```rust
check_strict!(MyEnum, -5..=20, expected_variants: 4);   // TryFrom<i32>; errors return the input
check_lenient!(MyEnum, -10..=20, expected_variants: 4); // From<i32> + to_num(); has Unrecognized(_)
```

The range must cover every valid value plus some invalid ones on both sides. `expected_variants` catches variants you forgot to map. Also add its `Default` to `enum_defaults()`. If it's stored in a `GDValue`, add it to the `check!` list in `roundtrips::gdvalue_strict_enums`.

### New `GDLevel` / `GDList` field

1. Set it to a non-default value in `sample_level()` / `sample_list()` in `mod.rs`.
2. Make sure `assert_levels_eq` / `assert_lists_eq` compare it. Sub-structs are compared through their `Debug` output, so a new field in an existing sub-struct is picked up automatically. A new top-level field needs a new line.
3. `deserialisers.rs`: the plist key is read, and a wrong plist type gives the default instead of a panic.
4. `serialisers.rs`: the key is written, and left out when it has its default value if GD does that too.
5. The existing round trips in `roundtrips.rs` and `files.rs` then cover it, because they use the sample level/list.

### New `CCGameManager` key

Field tests go in `deserialisers.rs` and use `gamemanager_string(body)` to build a minimal savefile. For no-panic cases, add one line to the `gamemanager_no_panic_tests!` list:

```rust
gamemanager_no_panic_tests! {
    gamemanager_non_string_my_key_does_not_panic => "<k>myKey</k><i>5</i>",
}
```

Each line becomes its own test, so a single panic doesn't hide the others.

### New file format / I/O function

Put it in `files.rs`:
- Read the checked-in samples in `test_gmds/`. Add a small new sample file if no existing one covers the format, and add `.gmd` levels to `TEST_LEVELS` so the "every test level" tests use it.
- Round trip: write it with `generated_path(...)`, read it back, compare.
- Error cases: missing file, wrong format, non-UTF-8 and non-dict content must return `Err` and must not panic.

### New game behaviour (formulas, RNG, …)

Put it in `game_logic.rs`. Use known input → output pairs from the real game (as `advanced_random_predict` does), plus edge cases: zero, negative, `i32::MAX` and NaN. Overflow should wrap like GD does, not panic.

## Writing good edge-case tests

For every new parser or serialiser, also test:
- empty input, a lone separator (`,`, `;`, `|`), and a trailing separator
- non-numeric text where a number belongs, numbers that overflow, negative ids
- unknown keys: they should be kept (in `other` / `unknowns`), not dropped
- unicode and XML special characters (`<>&"'`) in names and descriptions
- `Some(0)` vs `None`: GD often treats `0` as "unset", so check that it round trips the way you intend

Name no-panic tests `<thing>_does_not_panic`. The body only calls the function and ignores the result (`let _ = ...;`).

## When to create a new file

Don't make a new file for a new feature. Add to the existing files above. Create one only for a new **kind** of test that fits none of the categories, such as a whole new subsystem (a server API client, a new savefile with its own format and dozens of tests) or a new kind of check (property-based fuzzing, snapshot tests).

To add one:

1. Create `src/tests/<what_it_does>.rs`. Name it after what the tests *do* (`fuzzing.rs`, `server_requests.rs`), not after a struct.
2. Start it with a `//!` doc comment explaining what belongs in it. The crate uses `#![deny(missing_docs)]`.
3. Declare it in `mod.rs` in alphabetical order (`mod fuzzing;`) and add it to the module doc list at the top of `mod.rs`.
4. Add a row for it to the "Where does my test go?" table in this file.
5. Pull in helpers with `use super::{...};` and crate items with `use crate::...;`.

## Conventions

- Mark tests that need files you don't ship (`GMDS/...`) or that only dump output as `#[ignore]`, and prefix their names with `_temp_`.
- To avoid being tracked by git, all files generated by tests must start with `generated_`.
- Write output files only through `generated_path(...)`. Never overwrite files in `test_gmds/` that are checked in.
- Put context in assertion messages (`assert_eq!(a, b, "property {id}")`) so a failure in a loop says which case broke.
- Format new test files with `rustfmt --edition 2024 src/tests/*.rs`.
